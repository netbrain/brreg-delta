# SSR - Static Site Rendering for Entity Histories

This directory contains tools and templates for generating static HTML pages showing the complete history of changes for Norwegian business entities from Brønnøysundregistrene.

## Architecture

The system generates **one HTML page per entity** (2M+ pages total) showing a timeline of all changes to that entity over time. Each page is generated by running Hugo once with entity-specific markdown content.

### Components

1. **gen-history/** - Go tool for generating entity history pages
2. **entity-template/** - Hugo template for individual entity pages
3. **navigation-site/** - Hugo site for search/navigation index

### Data Flow

```
Git History → gen-history tool → Markdown → Hugo → HTML
                                              ↓
                                         Individual
                                         Entity Pages
```

## gen-history Tool

Command-line tool for generating entity history pages and search indexes.

### Installation

```bash
cd ssr/gen-history
go build -o gen-history .
```

### Usage

Must be run from the `brreg-data` repository (data branch) to access git history.

**Generate single entity:**
```bash
gen-history generate --orgnum 810034882 --output ./output
```

**Generate changed entities (incremental):**
```bash
gen-history generate --incremental --output ./output --workers 10
```

**Generate all entities (full rebuild):**
```bash
gen-history generate --all --output ./output --workers 20
```

**Generate everything (pages only, no search):**
```bash
gen-history all --output ./output --workers 20
```

### Options

- `--orgnum <num>` - Generate specific organization number
- `--incremental` - Only generate entities changed since last run (uses `.last-history-commit` state file)
- `--all` - Generate all entities (full rebuild, takes hours/days)
- `--output <dir>` - Output directory (default: ./output)
- `--workers <n>` - Number of parallel workers (default: 10)
- `--template <dir>` - Hugo template directory (default: ../entity-template)

## Implementation Details

### Git History Parsing

The tool uses `git log` to retrieve all commits affecting each entity:

```go
GetEntityHistory(dataDir, orgnum) -> []EntityChange
```

Each change includes:
- Commit hash and timestamp
- Commit message
- Full JSON data at that point in time

### JSON Diffing

Field-level diffing compares consecutive versions:

```go
DiffJSON(oldData, newData) -> []FieldDiff
```

Outputs:
- Field path (e.g., "organisasjonsform.kode")
- Old value
- New value

### Markdown Generation

Creates timeline markdown with:
- Frontmatter (title, orgnum, lastModified)
- Chronological timeline (newest first)
- Diff tables showing field changes
- Expandable sections with full JSON

### HTML Generation

For each entity:
1. Create temporary Hugo site
2. Copy entity-template
3. Write markdown to content/
4. Run `hugo --minify`
5. Extract and copy HTML to sharded output path

### Parallel Processing

Worker pool processes entities concurrently:
- Progress reporting every 100 entities
- Error collection and reporting
- Final statistics (total, successful, failed)

## Sharding

Entity pages are organized using triple-digit sharding based on organization number:

```
810034882 → 810/034/882.html
923456789 → 923/456/789.html
```

This keeps filesystem performance reasonable with 2M+ files.

## Performance Estimates

With 10 workers on typical hardware:

- **Single entity:** ~1-2 seconds
- **100 entities:** ~1-2 minutes
- **1,000 entities:** ~10-20 minutes
- **10,000 entities:** ~2-3 hours
- **2M entities (full):** ~100-400 hours (4-17 days)

Incremental mode typically processes 100-1,000 entities per day.

## Output Structure

Published to `gh-pages` branch:

```
gh-pages/
├── 810/
│   ├── 034/
│   │   └── 882.html          # Individual entity page
│   └── ...
├── .last-history-commit      # State tracking file
├── index.html                # Navigation site home
└── css/                      # Pico CSS from CDN
```

## Workflow

Automated GitHub Action (`.github/workflows/generate-history.yml`):

**Trigger:** Automatically runs after successful Brreg data sync workflow

**Process:**
1. Checkout master branch (code) and data branch (with full git history)
2. Checkout gh-pages branch (output destination)
3. Build gen-history tool
4. Install Hugo
5. Generate entity pages:
   - **First run:** Full rebuild of all entities (detects missing `.last-history-commit`)
   - **Subsequent runs:** Incremental (only entities changed since last commit)
6. Build navigation site (simple org number input form)
7. Commit and push to gh-pages branch
8. Save current data branch commit to `.last-history-commit` for next incremental run

**Manual trigger:** Supports full rebuild via workflow_dispatch with `full-rebuild: true`

**State tracking:**
- `.last-history-commit` file in gh-pages branch tracks last processed commit
- Incremental mode compares current HEAD with this commit to find changed entities

## Templates

### entity-template/

Minimal Hugo template for individual entity pages:
- Clean, responsive design
- Timeline with expandable sections
- Styled diff tables
- Links back to main navigation

### navigation-site/

Landing page with direct navigation:
- Simple organization number input field (9 digits)
- Client-side navigation to entity pages
- Converts orgnum to sharded path (810034882 → /810/034/882.html)
- Built with Pico CSS for semantic styling

## File Type Handling

The tool processes multiple file types per entity:

- **enhet.json** - Main entity data (name, address, organizational form, etc.)
- **underenhet.json** - Sub-entity data (if applicable)
- **roller.json** - Roles (board members, management, etc.)

Changes are grouped by file type with labels:
- "Enhetsendringer" for enhet.json changes
- "Underenhetsendringer" for underenhet.json changes
- "Rolleendringer" for roller.json changes

Each file type is compared only with previous changes of the same type to prevent cross-contamination.

## Translation

All field changes are translated to human-readable Norwegian:
- Entity fields: "Endret navn fra X til Y"
- Role changes: "La til Ole Hansen (Styreleder)", "Fjernet Kari Nilsen (Daglig leder)"
- Organizational forms, addresses, registration details, etc.
